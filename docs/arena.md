# Как устроена арена (своими словами)

Арена — эволюционный поиск решений задачи, где оркестрация задана не фреймворком, а промптами ролей и общим протоколом. Её главная ценность — гарантии честности эксперимента: исследователь не видит, на чём его в итоге оценивают, а история поиска полностью сохраняется.

**Роли и зачем каждая.**
- **Агент подготовки** превращает описание задачи в исполнимый пакет метрики, проверяет его и замораживает. Это отдельный запуск, чтобы метрику не подгоняли под найденные решения.
- **Оператор** (я) ставит зависимости, держит закрытые данные, запускает закрытые оценщики и выдаёт исследователям только URL и submit-токены.
- **Оркестратор** планирует поиск, раздаёт направления, следит за лимитом и выбирает финалистов.
- **Исследователи** в отдельных worktree делают шаг «гипотеза → изменение → замер на train».
- **Ревьюер** проверяет кандидатов перед финалом: не выходит ли изменение за разрешённую область, нет ли подгонки под train.
- **Private-оценщик** один раз оценивает K финалистов и выбирает N лучших.

**Видимость разделов.**
- Train открыт полностью: данные, эталоны, трейсы, свои подвыборки.
- Public возвращает только общий score: так кандидатов можно сравнивать без доступа к примерам, по которым подгоняют решения.
- Private не возвращает исследователю ничего, даже итоговых оценок. Это единственная честная оценка обобщения: на её результатах нельзя продолжать подбор, иначе private станет вторым public.
- В нашем кейсе к этому добавлено разбиение по семействам шаблонов: private проверяет не только новые значения, но и новые формулировки ([ADR-0004](adr/0004-data-and-split.md)).

**Лимит — число предложенных решений, а не токены.** Каждая версия, включая упавшие, занимает место. Это делает кривую эволюции сравнимой и честной: неудачи не выбрасываются, и нельзя бесконечно перебирать мелкие варианты. Токены и время измеряются, но лимитом не служат (у нас решатель без LLM, его токены = 0).

**Журнал, родословная, кривая, AUC.** `evaluator.search` хранит в SQLite каждого кандидата: гипотезу, изменение, родителей (их может быть несколько при слиянии подходов), снимок файлов и digest, все замеры с ключом сопоставимости (split, dataset, subset, conditions). Кривая — лучший score от номера решения. AUC показывает, как быстро поиск находит хорошее, а не только чего он достиг в конце: два поиска с одинаковым финалом, но разной скоростью, различаются по AUC.

**Финализация.** После исчерпания лимита или команды «стоп» оркестратор выбирает ровно K прошедших ревью финалистов: по качеству, разнообразию, устойчивости и риску переобучения. Пакет отправляется на private один раз в серии (seal), оценщик выбирает N лучших по метрике, при равенстве — по ресурсам. Результат видит только оператор.

**Граница изоляции в моей установке.**
- `operator/` (шаблоны и пулы генератора, `secret.json`, public/private JSONL) лежит вне Git до финализации. Исследователь получает чистую копию кейса: код генератора без содержимого, `train.jsonl`, метрику и baseline.
- Код кандидата исполняется только в одноразовом контейнере runner: `--network none`, read-only, кандидат смонтирован в `/candidate` только на чтение, вход через stdin.
- Метрика — доверенный код оценщика; исследователь её не меняет.
- Ограничение: если исследователи — агенты на той же машине с доступом к домашнему каталогу, границу держат права ФС (отдельный пользователь или контейнер исследователя без доступа к `operator/`), а не текст промпта. Это нужно настроить при подготовке (ЧП2).
