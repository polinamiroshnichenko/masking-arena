# ADR-0002: Формат задачи — два этапа (mask / unmask), метки `[КЛАСС_n]`, точный round-trip

- Статус: accepted (v1, до заморозки метрики может уточняться)
- Дата: 2026-11-06

## Контекст
Барьер стоит между агентом и внешней моделью и делает две вещи: перед отправкой заменяет ПДн метками (псевдонимизация), а в ответе модели возвращает реальные значения (деперсонализация обратно). Куратор: обратная подстановка нужна «с полным восстановлением» — если модель написала «Уважаемому [ФИО_1]», должно получиться «Уважаемому Иванову Ивану Ивановичу». Это ровно метод «введения идентификаторов» из приказа РКН № 140 от 19.06.2025: замена значений идентификаторами с таблицей соответствия, которая хранится отдельно.

## Решение
Экземпляр арены — один из двух типов (поле `task` во входе):

1. **mask**: вход — текст документа. Ответ — `{"masked_text", "replacements"}`, где `replacements` перечисляет каждое вхождение метки по порядку с исходной подстрокой. Метка — строго `[КЛАСС_n]`, класс из закрытого списка (`ФИО, АДРЕС, ТЕЛЕФОН, EMAIL, ПАСПОРТ, СНИЛС, ИНН, КАРТА, СЧЕТ, ДАТА_РОЖДЕНИЯ`), `n` — 1..k без пропусков внутри класса. Обязательное условие валидности — подстановка `original` вместо меток восстанавливает исходный текст символ в символ.
2. **unmask**: вход — словарь `{метка: каноническое значение}` и ответ «модели» с метками в любых падежах и с типичными искажениями (`[фио_1]`, `ФИО_1`, `[ФИО 1]`). Ответ — `{"text"}` с подставленными значениями в правильной грамматической форме; текст вне меток не меняется.

Какие фрагменты маскировать, считает метрика по токенам замаскированных интервалов, которые восстанавливаются из `replacements`.

## Альтернативы
- **Суррогаты вместо меток** (подставлять вымышленные ФИО/телефоны). Модели так естественнее, но обратная замена в свободном тексте неоднозначна (суррогат может совпасть со словом ответа или быть изменён моделью), а оценка требует знать суррогаты. Можно разрешить как вариант решения в v2, если формат меток станет узким местом.
- **Ответ — только спаны**, маскированный текст собирает оценщик. Проще, но тогда решатель не отвечает за то, что реально уходит модели (нумерация, согласованность меток), и навык придётся дописывать вне эволюции.
- **Сквозной экземпляр** «mask → реальная LLM → unmask». Честнее, но каждый замер тратит токены, недетерминирован, а LLM в контуре оценки противоречит идее дешёвой программной метрики (B-1.2). Сквозной сценарий проверим в тестах навыка (B-8.3).
- **Хэш/шифрование значения в метке** (как `encrypt` в Presidio). Утечка через метку и бессмысленные для модели токены.

## Последствия
- Round-trip проверяется детерминированно: удалить ПДн «молча», переписать текст или спрятать значение в метке нельзя — это ловят тесты `case/tests/test_metric.py`.
- Нумерация 1..k закрывает канал утечки через номер метки (`[ТЕЛЕФОН_9123]`).
- Этапы оцениваются раздельно; сохранение канонической формы на этапе mask (нужной для unmask в навыке) в v1 не оценивается — кандидат на v2.
