# ADR-0001: Методология — арена DeepPavlov без изменений протокола

- Статус: accepted
- Дата: 2026-11-06

## Контекст
Задание B требует эволюционной методологии с разделением исследователя и оценщика, разной видимостью train/public/private, заморозкой метрики до поиска, лимитом по числу решений, журналом с родословной и финализацией на private (B-0.2). Можно взять арену или собрать свою.

## Решение
Используем [арену](https://gitlab.deeppavlov.ai/deeppavlov/arena) как есть (проверенный коммит `669d9ed`, 2026-11-03): промпты `prepare.md` / `start.md`, журнал `evaluator.search`, закрытые оценщики `evaluator.service`, штатный немодельный runner. Кейс оформлен по `cases/template` и копируется в `cases/pii-masking-ru` арены. Метрика — `kind: command` с собственной агрегацией уровня набора (`aggregation`), что штатно поддерживается контрактом (`common/public-evaluation.md`).

## Альтернативы
- **Своя методология** (например, цикл OpenEvolve / ShinkaEvolve). Минус: всё, что арена уже даёт (изоляция public/private, журнал, AUC, ревью), пришлось бы повторять и доказывать. Плюс был бы только в контроле над промптами исследователей — для нашей задачи это не нужно.
- **Арена с изменённым протоколом** (например, батч-runner вместо контейнера на пример). Отложено: замер показал 0.31 с на пример через runner, public-оценка ~3 мин — узким местом не является.

## Последствия
- Отличий от арены нет, поэтому сравнительная таблица в `docs/arena.md` не нужна.
- Smoke арены пройдены (`docs/arena.md`), кейс проходит путь «freeze → verify → evaluate_answer → aggregate_results» на коде арены с тем же результатом, что локальный инструмент (`results/arena_smoke_metric.txt`).
- Возможный вклад в арену (B-0.4): пример кейса с агрегацией уровня набора и детерминированной программной метрикой; обсудить с командой арены после ЧП1.
