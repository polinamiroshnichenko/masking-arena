# ADR-0005: Решатель — локальная программа без обращений к LLM

- Статус: proposed (состав разрешённых библиотек фиксируется при подготовке кампании)
- Дата: 2026-11-06

## Контекст
Барьер существует, чтобы ПДн не ушли во внешнюю модель. Детектор, который сам отправляет текст в LLM, противоречит задаче, если LLM не локальная. Кроме того, арена эффективна, когда замер кандидата дешёвый, и тогда кампания может содержать сотни решений.

## Решение
Решатель — `solve.py`, немодельный режим runner арены: `network=none`, `uses_model: false`, вход через stdin, ответ через stdout. Baseline использует только stdlib Python 3.12. Для ML-кандидатов оператор до кампании соберёт отдельный образ runner с закреплёнными CPU-библиотеками и весами в `/assets`: кандидаты — natasha/slovnet (NER 27 МБ, CPU), pymorphy3 (склонение и лемматизация для unmask), razdel. Решение о составе фиксируется в `campaign.md` до поиска.

## Альтернативы
- **LLM-решатель через gateway арены.** Сильный детектор, но каждый замер стоит токенов, и это не барьер «до модели». Можно оставить как верхнюю оценку вне кампании.
- **Тяжёлые трансформерные NER** (DeepPavlov BERT, ~2 ГБ). На CPU в контейнере на пример загрузка занимает десятки секунд: по замеру авторов natasha, инициализация deeppavlov_bert — 34.5 с против 1.0 с у slovnet. Арена запускает контейнер на каждый пример, так что это ×600 на public.

## Последствия
- Токены решателя = 0, ранжирование при равном score — по времени (правило арены).
- Пространство решений: регулярки + контрольные суммы + контекстные слова + словари + малые NER-модели + морфология. Это и есть комбинации классических подходов из `docs/domain.md`.
