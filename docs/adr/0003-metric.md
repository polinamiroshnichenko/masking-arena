# ADR-0003: Метрика `pii-mask-v1` — H(recall по классам) · φ(precision) · точность восстановления

- Статус: proposed (черновик v1; замораживается при подготовке кампании, до поиска)
- Дата: 2026-11-06

## Контекст
Реестр: «recall и precision по классам ПДн, главное — recall при ограниченных ложных срабатываниях; корректность обратной подстановки». Куратор оставил выбор формулы и правила частичного совпадения нам (вопросы 4–5). Метрика должна быть программной, дешёвой и не поддаваться «жульническим» стратегиям: «замаскировать всё», «пропустить целый класс», «сломать текст».

## Решение
`score = H · φ(P) · A`, всё считается по набору (`aggregate.py`), а не как среднее по примерам.

1. **Единица recall — сущность, покрытие — по токенам.** Токены — последовательности букв/цифр. Покрытие сущности `cov` — доля её токенов, целиком попавших в замаскированные интервалы. Кредит сущности: `1`, если `cov = 1`; иначе `0.5 · cov`. Частичное маскирование засчитывается, но не больше чем наполовину: «Иванов [ФИО_1]» оставляет фамилию открытой — это утечка. Серия и номер паспорта — одна сущность.
2. **Recall класса** — средний кредит сущностей класса по набору. **H** — гармоническое среднее recall по классам, присутствующим в наборе. Если какой-то класс пропущен целиком, H = 0, и эволюция в первую очередь подтягивает слабейший класс.
3. **Precision P** — доля замаскированных токенов, которые принадлежат ПДн (micro по набору). Нейтральная зона (реквизиты организаций, детали выдачи паспорта) не учитывается ни в числителе, ни в знаменателе: по ответу куратора организации — вторая итерация. **φ(P) = min(1, P/0.9)²** — мягкий порог: пока P ≥ 0.9, штрафа нет, ниже — квадратичный.
4. **A** — доля верно восстановленных меток в unmask-примерах (micro по меткам). Сравнение после схлопывания пробелов и ё→е, с учётом регистра. Если текст вне меток изменён, метки этого примера не засчитываются.
5. **Невалидный ответ** (формат, сломанный round-trip, нумерация) не роняет проверку: для mask считается, что ничего не замаскировано, для unmask — ничего не восстановлено. Ошибка программы оценщика остаётся ошибкой проверки (контракт арены).
6. Направление — `maximize`, диапазон [0, 1]. Параметры (порог 0.9, степень 2, кредит 0.5) лежат в `case/metric/policy.json` и замораживаются вместе с пакетом.

## Почему так: поведение на эталонных стратегиях (train, 1700 примеров)
`results/metric_sensitivity/strategies.md`, команда — в README.

| **baseline** (regex + замена без склонения) | **0.286** | 0.645 | 0.645 | 0.747 | 0.996 | 0.443 | 0.844 | 0.774 |
| oracle + oracle | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 |

Что видно:
- **Токенный F2** (рекомендация Presidio для ПДн) ставит «замаскировать всё» на 0.730, почти вровень с baseline (0.774): recall-ориентированная F-мера вознаграждает тотальное маскирование. С мягким порогом precision эта стратегия получает 0.15.
- **Micro-метрики почти не замечают пропуск целого класса**: без номеров карт F1 = 0.968. Арифметическое среднее по классам снимает за такой пропуск лишь 10%. Гармоническое даёт 0: барьер, который пропускает все номера карт, не даёт гарантий.
- Частичная маскировка ФИО стоит заметно (0.782), но не обнуляет: эволюция получает градиент.
- Без восстановления падежей потолок score — 0.443. Требование куратора «полного восстановления» действительно влияет на оценку.

## Альтернативы
- **F1/F2 (micro или macro)** — см. таблицу: поощряют перемаскирование, не видят провала класса.
- **Жёсткий гейт** «P ≥ 0.9, иначе 0», дальше сравнение по recall. Даёт обрыв, на котором эволюция теряет градиент; мягкий φ даёт то же требование без обрыва.
- **Строгий entity-recall** (TAB: сущность защищена, только если замаскирована целиком). Корректен с точки зрения приватности, но без градиента; оставлен как диагностика (`strict_recall_by_class`).
- **Посимвольный recall**: длинные адреса весят больше коротких номеров; токенный recall внутри сущности устойчивее к границам («г.», «д.», пробелы).
- **Учёт правильности класса метки** (ПАСПОРТ вместо СНИЛС): для приватности не важен, для полезности модели — да. Пока это диагностика (`typed_recall_by_class`), кандидат в v2.
- **Веса классов** (прямые идентификаторы важнее даты рождения). Отложено до проверки на реальных текстах: H уже не даёт игнорировать ни один класс.
- **Восстановление как гейт (0, если не сработало)**. Слишком грубо: склонение ФИО в редких формах неоднозначно, нужна доля верных, а не «всё или ничего». Гейтом сделан только детерминированный round-trip на этапе mask.

## Последствия
- Шум: SE score baseline ≈ 0.011 на 600 примерах (public) и ≈ 0.009 на 900 (private). SE парной разности двух кандидатов на 600 примерах ≈ 0.005 (`results/data/bootstrap_*.json`). Различимое улучшение — от ~0.01.
- Компонент отсутствующего типа примеров опускается (train-подвыборка только из mask даёт H·φ). Такие замеры несравнимы с полными — ключ сопоставимости журнала включает подвыборку.
- После проверки на вручную размеченных реальных текстах (ADR-0004) метрика может измениться **до** заморозки: веса классов, учёт типа метки. После заморозки изменение = новая кампания.
