# ADR-0007: Исследователь — Claude Code в изолированном контейнере; минимальные лимиты; локальное развёртывание

- Статус: accepted
- Дата: 2026-11-20

## Контекст
Арену ведут агенты-исследователи. Изоляция по протоколу арены держится на правах доступа, а не на тексте промпта. Автор проекта и сессия, которая писала генератор, видели шаблоны и private, поэтому вести поиск сами они не могут. Модель по правилам курса должна иметь Intelligence Index Artificial Analysis не ниже DeepSeek Flash. Лектор советовал брать для арены Claude. Бюджет — подписка Claude Pro без API-ключа. К ЧП2 нужна идущая кампания с первой кривой и родословной.

## Решение
1. **Исследователь** — Claude Code 2.1.318 в контейнере `pii-researcher:1` (`deploy/researcher/`). Модель — Claude Sonnet 5.5, effort High: AA Intelligence Index v5.0.1 = 42 против 33 у DeepSeek V4.1 Flash (проверено 2026-11-20). При Medium индекс равен 31 и правилу не удовлетворяет, поэтому effort закреплён в скрипте запуска. Авторизация — токен подписки (`claude setup-token`), переданный в переменной окружения. В репозиторий и workspace токен не попадает.
2. **Граница изоляции.** В контейнер монтируются только `workspace/` (чистая git-копия арены с кейсом и train своей кампании), каталог журнала и три submit-токена. Файлов оператора, `data_idd/`, генератора с шаблонами и public/private в контейнере нет: проверено, `/Users` в контейнере отсутствует. Оценщики слушают 127.0.0.1 хоста и доступны из контейнера через `host.docker.internal`. Public отдаёт только score, private — только статус.
3. **Две арены по очереди:** сначала `mask`, затем `unmask` (ADR-0006), у каждой свой журнал, свои оценщики и свой образ решателя. Baseline общий и не меняется.
4. **Лимиты минимальные:** mask — 12 предложений (K = 3, N = 1), unmask — 6 (K = 2, N = 1). Каждое предложение получает public-оценку: по новому протоколу AUC считается только по public.
5. **Оценщики** работают процессами на хосте (`deploy/local/arena_ops.py`), без Compose и модельного gateway: решатель и метрика без LLM.

## Альтернативы
- **Hermes (эталонная интеграция арены) + DeepSeek/Claude по API.** Открытый харнес, учёт токенов через gateway арены. Но нужен платный API-ключ, а с подпиской Hermes не работает: Anthropic не разрешает использовать токен подписки в сторонних программах. Остаётся запасным вариантом, если лимитов Pro не хватит.
- **Поиск в этой же сессии Claude.** Нарушает изоляцию: сессия видела шаблоны и private.
- **Лимиты 90 + 30 (ADR-0006).** На подписке Pro кампанию не довести до конца к защите; честнее зафиксировать меньший лимит заранее, чем остановить поиск досрочно.
- **Docker Compose арены.** Рассчитан на Linux-узел (UID, сокет, сети). На macOS для немодельного кейса процессы на хосте проще и проверены приёмкой.

## Последствия
- Claude Code — закрытый харнес. Это допустимо для инструмента поиска (решение — открытый `solve.py`), но навык на ЧП3 проверяется на открытом харнесе (B-8.2).
- **Расход токенов исследования** не идёт через gateway арены, поэтому в журнале расход подготовки кандидатов «неизвестен» (`propose` без ресурсных аргументов). Фактический расход сохраняется в логах Claude Code (`operator/arena/<c>/logs/researcher-*.jsonl`, поле `usage` и стоимость сессии) и сводится в разборе отдельно, с пометкой «самоотчёт харнеса».
- Лимит подписки Pro прерывает сессии: `run.sh <c> continue` продолжает ту же сессию, состояние восстанавливается из журнала и `board/methods.md`.
- Отличия развёртывания (без `ARENA_SLOT_DIR`, особенности Docker Desktop) и результаты приёмки — в `docs/preparation.md`.
- Маленький лимит означает короткую кривую: AUC и выводы о сходимости будут грубыми. Вторая кампания (бонус B-5.3) — при наличии лимита.
