# Правила разметки реальных документов (проверочная выборка)

Выборка нужна, чтобы проверить перенос метрики и решения с синтетики на реальные тексты (реестр тем, правило про синтетику; карточка AR-05). Она **не участвует в поиске**, не входит в train/public/private и не видна исследователям. Тексты, разметка и спецификация хранятся у оператора в `operator/real_check/` вне Git; в репозитории — только сводка `results/real_check/summary.md`.

Классы — те же 10, что в кейсе. Разметка в формате train (`tools/annotate.py`): каждый фрагмент `[[КЛАСС|…]]`, нейтральная зона `[[~ORG|…]]`.

| Что в тексте | Разметка | Почему |
|---|---|---|
| ФИО любого человека в любой форме: полностью, с инициалами, в косвенном падеже, с переносом строки, ВЕРХНИМ РЕГИСТРОМ, с опечаткой OCR | `ФИО` | персональные данные независимо от должности |
| Имя в названии организации или подразделения («им. И.В. Курчатова») | не размечается | часть названия, не данные о субъекте |
| Контактный телефон, указанный при конкретном человеке (исполнитель, ИП), в т. ч. рабочий | `ТЕЛЕФОН` | позволяет связаться с конкретным лицом |
| Общий телефон организации (шапка бланка, 8-800, реквизиты юрлица) | `~ORG` | данные юрлица; если один номер встречается и как общий, и при человеке — по первому смыслу (общий) |
| Именная почта (`ivanov.ii@…`, личная gmail) | `EMAIL` | |
| Ролевой или общий ящик (`info@…`, `zakupki@…`) | `~ORG` | |
| ИНН из 12 цифр (физлицо, ИП) | `ИНН` | ИП — физическое лицо |
| ИНН из 10 цифр, КПП, ОГРН, ОКПО, БИК, корр. счёт, расчётный счёт юрлица (40702…) | `~ORG` | реквизиты организации, вторая итерация (ответ куратора) |
| Расчётный счёт ИП / физлица (40802…, 40817…) | `СЧЕТ` | |
| Адрес регистрации ИП, физлица | `АДРЕС` | |
| Адрес организации (юридический, почтовый, адрес здания) | `~ORG` | |
| ОГРНИП, детали выдачи паспорта (кем выдан, дата выдачи, код подразделения) | `~ORG` / `~PASSPORT_ISSUE` | не входят в 10 классов; маскирование не штрафуется и не требуется |
| Серия и номер паспорта, СНИЛС, дата рождения | `ПАСПОРТ`, `СНИЛС`, `ДАТА_РОЖДЕНИЯ` | |
| Серийные номера сертификатов ЭП, GUID, номера документов и заявок, суммы, даты документов | не размечаются | не ПДн по схеме кейса |
| Пустые бланки с местом под ПДн («ФИО ______») | документ без сущностей | проверка на ложные срабатывания |

Качество: после разметки скрипт ищет в тексте неразмеченные фрагменты, похожие на ПДн (инициалы, отчества, почты, длинные числа); все оставшиеся совпадения разобраны вручную (номера документов, суммы, «М.П.», «Ф.И.О.» в бланке, имя в названии подразделения).

Ограничения: разметку выполнял агент, автор проекта проверяет её выборочно; в выборке мало редких классов (1 паспорт, 1 дата рождения, 2 СНИЛС, нет карт) — для них выводы по реальным текстам слабые.
